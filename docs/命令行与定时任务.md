# 命令行与定时任务

除了管理面板，本项目也可以用命令行直接操作。`main.py` 是入口，`panel.py` 是面板服务。

> **定时有两条链，别混用**：
> ① **面板「定时任务」页 = 任务条目库 + 常驻守护进程**（SCH-001，**推荐**）——不依赖 Windows 计划任务；
> ② **命令行 `python main.py HH:MM` = 注册 Windows 计划任务**（`schtasks`，兼容旧用法/迁移收尾）。
> 两条链共用同一套执行入口（`panel.trigger_run`）与跨进程 `.running` 守卫。

---

## 一、`main.py` 用法

### 交互模式（直接运行）

```bash
python main.py
```

多账号时先选账号（只有一个账号时自动沿用，不再询问）：

```
可用账号：
  [1] main
  [2] backup
请选择账号（输入序号或别名，回车默认第一个）：
==========================================
       抖音自动续火花（账号: main）
  [1] 手动触发   = 立即给所有目标发一次
  [2] 定时触发   = 设为每天定时自动发
==========================================
请选择 (1=手动 / 2=定时)：
```

- 选择后输入要发送的内容（每行一条，可多条用于随机轮换，空行结束）。
- **手动触发（选 1）**：用本次输入内容**立即**给该账号的 `targets` 各发一次，**不改动配置文件**（走跨进程 `.running` 守卫）。
- **定时触发（选 2）**：再输入时间（如 `21:30`），把时间与内容写回该账号的 `user_data.yaml`，并注册 Windows 计划任务 `DouyinAutoFire-<别名>`（即上面第二条链；要改用守护定时请走面板）。
- 零账号 / 旧数据未迁移时，交互模式会给出提示（先 `--migrate` 或开面板添加账号）而不报错退出。

### 非交互用法（多账号 MAI-001）

```bash
python main.py --run-once --account main     # 立即给账号 main 发送一次
python main.py 21:30 --account main          # 账号 main 每日 21:30 定时（注册 Windows 计划任务）
python main.py --setup-login --account main  # 打开浏览器供账号 main 登录/解验证码（不发送）
python main.py --migrate main                # 迁移旧版单账号数据到账号 main
python main.py --list-accounts               # 列出所有账号别名
python main.py --test                        # 仅验证依赖与浏览器能否启动（免账号）
```

参数说明：

| 参数 | 含义 |
| --- | --- |
| 位置参数 `HH:MM` | 直接设为该账号每日定时（注册 Windows 计划任务，非交互） |
| `--account <别名>` | 指定账号别名 |
| `--run-once` | 立即发送一次后退出（供任务计划程序调用） |
| `--setup-login` | 仅打开浏览器供手动登录 / 解验证码，不发送（走跨进程守卫） |
| `--migrate <别名>` | 把旧版单账号数据迁入 `accounts/<别名>/`（幂等，走守卫） |
| `--list-accounts` | 列出所有账号别名（每行一个） |
| `--test` | 仅测试依赖与浏览器启动（免账号） |

**账号解析规则**（`--run-once` / `HH:MM` / `--setup-login` 等非交互路径）：

- `--account` 显式给 → 用之（不存在/非法则报错列出可用别名，exit 2）；
- 未给且恰 1 个账号 → 自动沿用（单账号零打扰）；
- 未给且多个账号 → 报错列出别名，exit 2（不默认跑第一个，防串号）；
- 未给且检测到旧版数据 → 提示先 `--migrate <别名>`，exit 2；
- 零账号且无旧数据 → 提示先在面板添加账号，exit 2。

## 二、定时链一：面板任务库 + 常驻守护（SCH-001，推荐）

面板「定时任务」页四张卡：**守护进程** / **定时任务列表** / **新建定时任务** / **旧版迁移与清理**。

### 机制

- **任务条目库**：`userdata/scheduler_jobs.json`（由 `jobs.py` 读写）。每条任务自带账号 / 每天时刻 / 目标 / 文案的**独立副本**——改某号的手动配置不影响已建任务。唯一写方是面板 CRUD 与一键迁移。
- **常驻守护**：`scheduler_daemon.py`（约 20 秒主循环）——
  - 到点把任务入队，**串行**执行（同一时刻只跑一个，沿用跨进程 `.running` 守卫）；
  - **错峰固定 15 分钟**（`DAEMON_STAGGER_MINUTES = 15`）：同刻多个任务自动依次错开；
  - 错过当天时刻（如电脑当时关机）→ 恢复后**补跑一次**；
  - 心跳写 `userdata/scheduler_heartbeat.json`，运行/队列状态写 `userdata/scheduler_state.json`；
  - 两段式落盘（先 `dispatching` 再 `running`），崩溃复核不重发。
- **开机自启**：写注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 值 `DouyinAutoFireScheduler`（**无需管理员权限**）；面板守护卡上的「开机自启」复选框即这个开关。
- **启动 / 停止**：面板守护卡的「启动守护」「停止守护」（停止时运行中的任务自然跑完再退出）、「取消当前队列」。

### 与旧版 schtasks 定时的关系

旧版「每号一条 Windows 计划任务」可用面板「定时任务 → 旧版迁移与清理」收尾：

- **一键迁移**：把该号 `schedule.time` + 全量目标转成任务条目（幂等，不重复生成）；
- **清理旧系统任务**：一次性删除 `DouyinAutoFire-<别名>` 系列计划任务。

## 三、定时链二：命令行注册 Windows 计划任务（兼容）

### 注册方式

**方式 A：通过 `main.py`**
交互选 2，或非交互 `python main.py 21:30 --account <别名>` → 内部用 `schtasks` 注册 `DouyinAutoFire-<别名>`。

**方式 B：手动（可选）**

已删除 `setup_windows_task.ps1`：它用 `Register-ScheduledTask`（COM），
在面板的后台子进程（MTA 公寓模式）里会失败。`main.py` 统一使用 `schtasks` 命令行。

### 任务画像

- **任务名**：`DouyinAutoFire-<别名>`，**每账号一条**（别名限英文/数字/下划线，任务名纯 ASCII）。旧版单任务名 `DouyinAutoFire` 仅在迁移收尾时用于删除。
- **级别**：**普通用户级任务**（登录时运行即可），**不需要管理员权限**。
  - ⚠️ 不要加 `/RL HIGHEST`（最高权限），普通用户会「拒绝访问」。
- **触发器**：每天 `ST` 指定的时间（`/SC DAILY`）。**多账号请错峰 ≥15 分钟**（如 21:00 / 21:30）——跨进程 `.running` 守卫保证同一时刻绝不并发，错峰避免撞车时后一个号被跳过。
- **操作（Action）**：`"<pythonw.exe>" "<项目>\runner.py" --run-once --account <别名>`
  - 用 **`pythonw.exe`** 而非 `cmd /c python`：到点不会弹出控制台黑框。
  - `runner.py` 自己 `chdir` 到项目根，并把任何早期异常（依赖缺失等）写进 `run.log`，
    杜绝「任务 exit 1 但日志一片空白」的黑盒。
  - 解释器路径由 `pyenv.py` **每次注册时重新探测并校验**（必须能 `import playwright`），
    不再硬编码——避免 venv 被删/迁移后任务静默失效。
- **运行状态**：成功注册后默认「已启用」。

### 启用 / 禁用 / 删除

等价命令（把 `<别名>` 换成实际账号）：

```bash
schtasks /Change /TN DouyinAutoFire-<别名> /Enable
schtasks /Change /TN DouyinAutoFire-<别名> /Disable
schtasks /Delete /TN DouyinAutoFire-<别名> /F
```

判断某号是否已注册（面板「定时任务 → 旧版迁移与清理」会列出，或命令行）：

```bash
schtasks /Query /TN DouyinAutoFire-<别名> /FO LIST /V
```

### ⚠️ headless 与抖音风控（重要）

实测：`browser.headless: true` 时抖音**必定**弹出拼图滑块验证，任务立刻停手，一条也发不出去。

所以无论哪条定时链，都必须用 **真实有头浏览器**（`config.yaml`）：

```yaml
browser:
  headless: false     # 真实有头浏览器，指纹正常，不触发风控，窗口正常显示在屏幕内
```

> 定时任务运行时浏览器窗口是可见的（会弹出一个 Chrome 窗口）。若希望它不抢焦点，请勿最小化/移动窗口——保持 `headless: false` 即可，抖音对无头浏览器风控最严。
> ⚠️ 多账号期间 `browser.real_chrome_profile` 必须保持 `false`（为 true 会绕过账号隔离、两号共用登录态而串号）。

### 健康自检

面板 `/api/tasks`（当前账号）返回 `health` 字段，自动检查三类历史故障：

1. 旧计划任务指向的 `python.exe` 已不存在（venv 被删/迁移）；
2. 本机找不到可用的 `.venv`；
3. `headless: true`（会被风控拦截）。

### 定时不生效时的排查顺序

1. **面板守护链**：守护卡是否显示「运行中」；不是就点「启动守护」（或勾「开机自启」）。任务条目是否「启用中」、时间是否正确；错过当天时刻守护会补跑一次。
2. **命令行/旧 schtasks 链**：`schtasks /Query /TN DouyinAutoFire-<别名>` 看任务是否存在、是否被禁用（见 [docs/故障排查.md](故障排查.md) 第 5 节）。
3. 两条链都别忘 `headless: false`。

> `main.py` 若注册计划任务失败（多半是安全软件/组策略拦截 `schtasks`），只会在日志里报错退出，**不再退化为常驻循环**——改用面板「启动守护」即可获得常驻定时，无需管理员权限。

## 四、项目内置脚本（.bat）

| 文件 | 用途 |
| --- | --- |
| `启动项目.bat` | 双击启动管理面板（后台无窗口）：先清理旧实例占用的端口，再以 `pythonw` 拉起 `panel.py`，就绪后自动打开浏览器到 `http://127.0.0.1:8765`。 |
| `关闭项目.bat` | 双击停止后台面板服务（按命令行匹配 `panel.py` 进程强杀整个进程树，并释放 8765 端口）。 |

> 只有这两个脚本；更早版本的 `启动面板.vbs` / `启动面板.bat` / `停止面板.bat` / `抖音续火花.bat` **均已删除**，文中若见旧名请以本表为准。
> 两个脚本用 `powershell` 定位进程并 `taskkill /T`，不依赖 `wmic`；面板本体监听端口由 `config.yaml` 的 `panel.port` 决定（默认 8765）。

## 五、启动方式备注（pythonw vs python）

- `启动项目.bat` 使用 `pythonw.exe`（无控制台窗口）。
- 在部分后台托管/沙箱环境下 `pythonw` 可能异常退出（exit 码异常）。若发现面板起不来，**改用 `python.exe panel.py` 前台启动**最稳妥（多占用一个终端窗口）。
- 无论哪种方式，重复启动都会先清理旧实例占用的端口。
- 面板日志统一写在 `userdata/panel.log`（`pythonw` 无控制台）；命令行运行的日志由 `config.yaml` 的 `logging.file` 指定（默认 `userdata/run.log`）。
