# 故障排查

常见问题与解决办法。若遇到不确定的情况，优先查看「执行记录」里的**完整日志**和**证据截图**，结合本文档「找不到会话：真 vs 假」一节判断。

---

## 1. 面板打不开 / 一直「加载失败」

- **用 `file://` 打开了 `panel.html`**：浏览器地址栏若是 `file:///.../panel.html`，面板连不上本地服务，「定时任务」「执行记录」会一直「加载失败」。请改用 `http://127.0.0.1:8765`（双击 `启动面板.vbs` 会自动打开该地址）。页面已内置「打开方式不对」提示。
- **面板服务没启动**：确认是否双击了启动脚本 / 运行了 `python panel.py`。可在浏览器直接访问 `http://127.0.0.1:8765`，若连不上说明服务未起。
- **端口被占用**：若提示端口被占用，可能已有旧面板实例。`停止面板.bat` 或任务管理器结束 `python.exe` / `pythonw.exe` 中的 `panel.py` 进程后重试。

---

## 2. 端口被占用 / 启动报 “port already in use”

- `面板` 启动时会自动清理命令行匹配 `panel.py` 的旧进程；若仍失败，手动结束占用 8765 端口的进程：
  ```bash
  netstat -ano | findstr "8765"
  # 找到 PID 后
  taskkill /PID <PID> /F
  ```
- 或修改 `config.yaml` 的 `panel.port` 换一个端口，重启面板。

---

## 3. 「找不到会话」：真的没找到，还是误判？

这是本工具历史上最易混淆的问题。现在每次失败都会**自动留审计证据**，请这样判断：

1. 打开「执行记录」里对应的那次运行，看**证据截图**与**日志摘要**（格式：`[审计-<tag>] 目标=… | 右侧当前=… | 编辑器=… | 编辑器文本长度=… | 列表项=…`）。
2. **真找不到**（建议手动/改配置）：
   - 日志里 `列表项` 里根本没有目标昵称 → 说明抖音列表里确实没有这个名字（精确等值匹配，无前缀匹配）。常见原因：昵称拼写不符（含特殊字符/空格/emoji）、该会话已被删除、或目标在更深的子列表里。
   - 解决：去抖音确认昵称，或在面板「选会话」里重新「一键同步」后勾选保存（最稳妥）。
3. **误判**（匹配到了但校验不过）：
   - 日志里 `列表项` 含有目标名，但右侧标题/选中态读不到 → 说明会话其实打开了，只是校验逻辑没读到。新版确定性锚点（`curConversation` / `.RightPanelHeadertitle`）已大幅缓解；若仍触发，记 `switch_fail` 审计并跳过（不发错人）。
   - 若出现「私聊发到群聊」「群聊多发」等发错人现象，见第 4 节。
4. 微调建议：确认 `targets[].name` 与抖音会话列表里显示的名称**完全一致**（现已改为精确匹配，不再做前缀匹配）。群目标填**纯群名**，不要带 `(人数)` 后缀。若仍匹配不到，查看审计 JSON 里 dump 的实际列表项标题做比对。

---

## 4. 私聊消息发到了群聊 / 群聊被多发

历史上出现过「目标会话没切过去，消息发到了上一个还开着的会话」的情况。根因是匹配逻辑误命中了**右侧已打开面板里的消息内容**（例如对方昵称恰好出现在群消息里），导致 IM 浮层被关闭或切错。

已修复：所有会话匹配现在都**限定在左侧会话列表容器内**（锚点 `[data-e2e="conversation-item"]`），不会命中右侧聊天内容。`_send_text` 发送前会用双信号校验（`curConversation` 选中态 + 右侧标题）确认当前打开确为目标会话，不符会记 `wrong_conversation` 并跳过（不发错人）。若你仍观察到发错人：

- 看「执行记录」里该次的 `wrong_conversation` / `switch_fail` 审计截图。
- 确认 `config.yaml` 里 `targets[].type` 正确（私聊=private，群聊=group）。

---

## 5. 定时任务注册失败 / 点「保存并注册」没反应

- **点保存后提示成功但实际没任务**：老版本前端误把 HTTP 200 当成功，后端其实返回了错误信息。现已改为以返回 JSON 的 `ok` 字段为准，失败会明确提示。若仍无任务，看「执行记录」或 `panel.log`。
- **「系统定时任务被拒绝访问」**：通常是安全软件/组策略拦截 `schtasks`。可尝试**「以管理员身份」启动面板**后再点「保存并注册定时任务」。注意：本工具用的是**普通用户级任务（不加 `/RL HIGHEST`）**，本不需要管理员；若仍被拒，多半是环境策略限制。
- **手动验证 schtasks 是否可用**：
  ```bash
  schtasks /Query /TN DouyinAutoFire
  ```
- 若注册始终失败，可退化为 `main.py` 内置常驻循环（见 [命令行与定时任务](命令行与定时任务.md)），但需保持窗口常开。

## 6. 安全验证（滑块/拼图/验证码）

- 触发本身会弹出**可见浏览器**。一旦 `run()` 检测到验证，会**立即停手**并标记状态为「需验证」。此时：在弹出的浏览器里**手动完成验证**，关闭窗口，回到「一键触发」重新点「前台触发」即可。
- 若当时没处理，去「一键触发」页点「打开浏览器」，手动完成验证后关闭窗口，再重新触发。
- 程序**不会、也不应**自动破解验证码。

---

## 7. 浏览器数据目录被占用（lock）

- 报错含 `lock` / `user_data_dir` / `browser context`：说明另一个浏览器实例正在使用同一 `user_data_dir`（`browser_data/`）。
- 关闭：你正在用的 Chrome（若开了 `real_chrome_profile`）、其它面板触发窗口、或残留的 chromium 进程。
- 任务管理器结束 `chrome.exe` / `chromium` / 占用 `browser_data` 的 python 进程后重试。

---

## 8. 登录态失效

- 现象：运行时停在扫码登录或反复要求登录。解决：面板「一键触发」页点「打开浏览器」扫码登录；或把 `browser.headless` 临时改 `false` 后 `python main.py --setup-login` 扫码。登录成功窗口会自动关闭，之后改回 `headless: true`。
- 登录态落在 `browser_data/`，**不要删除该目录**，否则需重新扫码。

---

## 9. `pythonw` 后台启动失败

- 在某些后台托管/沙箱环境下 `pythonw.exe`（无窗口）会异常退出（exit 码异常），表现为面板起不来。
- 解决：用 `python.exe panel.py` **前台启动**（多一个终端窗口，但最稳）。本项目「启动面板.bat / .vbs」默认用 `pythonw`；如遇问题请改用 `python panel.py`。

---

## 10. 中文乱码 / 报错信息出现 `���`

- 早期版本解码 `schtasks` / PowerShell 输出时按 UTF-8 解析，中文 Windows 实际是 GBK，导致乱码。
- 现已修复：`_decode_output` 会先按 UTF-8，失败再回退 GBK/GB2312/CP936。若你仍看到乱码，请升级到最新代码（`py_compile panel.py douyin.py` 通过）。

---

## 11. 日志在哪里

| 场景 | 位置 |
| --- | --- |
| 面板后台运行 | `panel.log`（根目录，唯一日志出口） |
| 命令行运行 | `run.log`（由 `config.yaml` 的 `logging.file` 指定） |
| 单次运行详情 | `runs/<id>.log`（「执行记录」详情里可看） |
| 证据截图 | `runs/<id>/`（「执行记录」详情里的「证据截图」） |
| 审计 JSON | `runs/<id>/audit_<tag>_<HHMMSS>.json` |

> 每次运行只保留最近 3 条记录，更早的会被自动彻底删除（含截图目录）。
