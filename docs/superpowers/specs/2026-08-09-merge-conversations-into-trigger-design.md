# 设计：把「选会话」合并进「一键触发」

日期：2026-08-09
状态：已确认（用户选方案 A）

## 背景
现版面板顶部有 4 个 tab：一键触发 / 选会话 / 定时任务 / 执行记录。
「选会话」其实是「一键触发」的前置配置——选好会话，「一键触发」才按这些会话逐一发送。
用户希望把会话选择并入「一键触发」页，不再单独占一个 tab，减少切换。

## 选定方案：A —— 上下双卡，会话区可折叠
- 顶部 tab 改为 3 个：一键触发 / 定时任务 / 执行记录（删除「选会话」tab）。
- 「一键触发」section 内放两张卡片，上下排列：
  1. **立即发送一次**卡（保留原样）：内容框 + 前台触发/保存内容/打开浏览器 + 实时日志。
     - 「前台触发」按钮内加徽标：`→ N 会话`（N = 已选会话数），直观提示发送目标数量。
  2. **目标会话**卡（原「选会话」内容搬来）：默认**折叠**，头部只显示标题 + 「已选 N」徽标 + 点开管理箭头。
     - 点头部整条展开/收起（CSS max-height 过渡）。展开后显示：说明、一键同步/全选/反选/保存所选按钮、`#convListWrap` 列表、底部状态行。
- 折叠状态用一份 CSS（`.card.foldable > .summary` + `.fold-body`）实现，不引入新 JS 框架；展开交互用一行 `onclick` 切 `.open` class。

## 布局细节
- 折叠卡结构：
  ```
  <section class="card foldable" id="convCard">
    <div class="summary" onclick="toggleFold('convCard')">
      <h3>目标会话</h3>
      <span class="badge ok">已选 N</span>
      <span class="muted">点开管理 ▾</span>
    </div>
    <div class="fold-body"> ...原选会话内容... </div>
  </section>
  ```
- 初始渲染时根据已选会话数决定默认展开/折叠：有已选则折叠（常驻配置好了），无已选则展开（引导用户先同步）。为简单起见，首版统一默认折叠，徽标显示当前已选数。

## 数据 / 接线（不动逻辑）
- 所有现有 JS 钩子保留原 id：`#convListWrap`、`#syncBtn`、`#selAllBtn`、`#selInvBtn`、`#saveTargetsBtn`、`#syncHint`。
- `renderConvList()` 仍注入到 `#convListWrap`，容器移入折叠卡内即可，逻辑零改动。
- `panel.py` 后端无需改动（tab 是纯前端概念，会话缓存/同步 API 不变）。

## 触发按钮徽标
- 在 `refreshState()`（或等价状态刷新处）里，读取已选会话数，更新「前台触发」按钮内的 `<span class="badge brand">→ N 会话</span>`。
- 若未选任何会话，徽标显示「→ 0 会话」并可将触发按钮提示文案改为「请先选会话」。

## 验收标准
1. 顶部只剩 3 个 tab，无「选会话」。
2. 「一键触发」页含两张卡：立即发送（常驻）+ 目标会话（默认折叠）。
3. 点「目标会话」头部可展开，内容与原「选会话」页一致（同步/勾选/保存均可用）。
4. 「前台触发」按钮显示已选会话数徽标，与实际选中数一致。
5. 折叠/展开动画流畅，尊重 `prefers-reduced-motion`。
6. 响应式：窄屏（≤768px）下两张卡仍正常堆叠、可点。
7. 现有同步、触发、保存内容功能经实跑验证不回归。

## 范围外
- 不重做「定时任务」「执行记录」页。
- 不改后端 API。
- 不调整触发逻辑本身（可见浏览器、安全验证手动处理等保持原样）。
