- **状态**: **IMPLEMENTED**（2026-10-04；`verify.py` **170/0**、exit 0；面板热刷新即可生效，无需重启进程）
- **特性**: 「一键触发」页的消息框与当前账号绑定——**切换账号时无条件载入该账号已保存的内容**（未保存过则清空），不再残留上一个账号的文案
- **触发**: 用户 (m00658) 报 bug：「立刻发送一次这个板块有问题，我切换账号了，但是要发送的内容没有切换，应该切换为每个账号各自保存的内容」
- **Spec / Plan**: 无（有界 bug 修复，未单独立 spec；决策与验证证据记录在本文件与 `CHANGELOG.md`）

## 缺陷与根因

- **现象**: 账号 A 的消息框里是 A 的文案，切到账号 B 后文本框内容不变，仍显示 A 的文案；此时点「前台触发」会把 **A 的文案发给 B 的账号**（后端 `panel.py:502-504` 以请求体 `texts` 覆盖 `cfg["message"]["texts"]`，前端 `doTrigger()` 正是从文本框取值）。
- **根因**: `panel.html:561-564` 的预填守卫是「**仅首次 / 为空时**」：

  ```js
  // 预填消息框（仅首次/为空时）
  const mi = $("#msgInput");
  if (mi.value.trim() === "" && s.message_texts && s.message_texts.length)
    mi.value = s.message_texts.join("\n");
  ```

  只要框里非空就永不覆盖，而 `setActiveAccount()`（`panel.html:1263-1276`）切号时只重置了会话缓存/执行记录，**没有重置消息框**，于是上一个账号的文案一直留着。后端本身没问题：`/api/state` 返回的是 `activeAccount` 的 `message_texts`。

## 设计

- 新增模块级状态 `msgAccount`（消息框当前承载的是哪个账号）与 `msgLoaded`（载入时的原文，用于识别「未保存的编辑」），以及 `applyMsgText(texts)` 统一写入。
- `refreshStatus()` 中改为**按账号判等**：`activeAccount !== msgAccount` 时**无条件**用新账号的 `message_texts` 覆盖（无内容则清空）；同一账号内仍保留「框为空时才预填」，避免打断正在编辑的内容。
- 替换前若框里有非空且与 `msgLoaded` 不同的内容，弹一条 toast 提示「已切换到 X，消息框已换为该账号保存的内容」，**不静默吞掉用户输入**。
- `保存内容` 成功与 `前台触发` 成功后同步 `msgLoaded`（这两条路径后端都会持久化），避免切号时误报「未保存的编辑」。
- **不改后端**：`/api/state`、`/api/save-message`、`/api/trigger` 的账号语义本来就正确（经 `api()` 的 `opts.account || payload.account || activeAccount`）。
